Young Engineers: Das UND-Gatter als eigener Minecraft-Block

← Logikblöcke · Redstone-UND-Gatter · Eigene Mods

Unsere Mission: Eine Redstone-Schaltung aus mehreren Bauteilen wird zu einem einzigen programmierbaren Block. Wir lernen dabei die Verbindung von Digitaltechnik, Java und Minecraft-Modding.

1. Was unser Block können soll

Der Block erhält zwei Eingänge und einen Ausgang. Er kann waagerecht gedreht werden, ohne dass sich seine Funktion ändert. Ein aktiver Eingang bedeutet: Redstone-Signalstärke größer als 0. Ein aktiver Ausgang liefert die Stärke 15.

Entwurfsskizze: zwei Eingänge, ein Ausgang. Die genaue Lage der Minecraft-Blockseiten wird im nächsten Bild festgelegt.

2. Draufsicht – die Anschlüsse sind eindeutig

Der Block schaut zunächst nach Süden (im Bild nach unten). Eingang A liegt links (= Osten, wenn man in Blickrichtung Süden schaut), Eingang B rechts (= Westen), Ausgang Q vorne (= Süden). Die Rückseite hat keinen Anschluss. Wir verwenden hier bewusst eine festgelegte Konvention, die wir beim Programmieren und Testen unverändert beibehalten.

Achtung zur Orientierung: Bei Blickrichtung Süden ist Osten links aus Sicht der Figur, aber rechts auf einer Karte mit Norden oben. Darum benutzen wir für das Programm vor allem Himmelsrichtungen und testen jede Drehung ausdrücklich.

3. Interaktiver Schaltungstest

Schalte A und B ein oder aus. Der Simulator berechnet sofort Q = A && B. Dieser Test funktioniert direkt im Browser, noch ohne Minecraft.

Q: AUS (0)

Beide Eingänge sind aus. Der Ausgang bleibt aus.

ABQ
000
010
100
111

Dein Auftrag: Probiere alle vier Kombinationen aus. Warum reicht ein einzelner eingeschalteter Hebel nicht aus?

4. Unser erster Java-Baustein: die reine Logik

Bevor wir uns mit Minecraft-Klassen beschäftigen, programmieren wir die Wahrheitstabelle als kleine Java-Funktion. Dieser Code ist normales Java und unabhängig von der Fabric-API.

package de.mrge.youngengineers.logic;

public final class UndLogik {
    private UndLogik() {}

    public static boolean berechne(
            boolean eingangA,
            boolean eingangB) {
        return eingangA && eingangB;
    }

    public static int signalstaerke(
            int signalA,
            int signalB) {
        boolean a = signalA > 0;
        boolean b = signalB > 0;
        return berechne(a, b) ? 15 : 0;
    }
}

Erklärung: && bedeutet logisches UND. Mit signalA > 0 wandeln wir die Minecraft-Signalstärke (0 bis 15) in EIN oder AUS um. Der Ausgang wird entweder 15 oder 0.

5. Java zunächst ohne Minecraft testen

Erstelle im gleichen Java-Paket die Klasse UndLogikTest.java (zunächst als einfaches Testprogramm). Sie kann unabhängig von der Mod-Registrierung gestartet werden.

package de.mrge.youngengineers.logic;

public class UndLogikTest {
    public static void main(String[] args) {
        pruefe(0, 0, 0);
        pruefe(0, 15, 0);
        pruefe(15, 0, 0);
        pruefe(15, 15, 15);
        pruefe(1, 1, 15);
        pruefe(0, 1, 0);
        System.out.println("Alle UND-Tests bestanden!");
    }

    private static void pruefe(int a, int b, int erwartet) {
        int q = UndLogik.signalstaerke(a, b);
        if (q != erwartet) {
            throw new AssertionError(
                "A=" + a + ", B=" + b +
                ": erwartet " + erwartet + ", erhalten " + q
            );
        }
    }
}

Führe die main-Methode in VS Code über die Java-Erweiterung aus. Erscheint Alle UND-Tests bestanden!, ist die mathematische Funktion korrekt implementiert. Der Test beweist noch nicht, dass die Minecraft-Redstone-Anbindung funktioniert.

6. Der nächste Java-Schritt: Minecraft-Anbindung

Jetzt wird aus der normalen Java-Funktion ein Minecraft-Block. Die technische Umsetzung besteht aus sechs überschaubaren Aufgaben:

  1. Block registrieren: Wir legen die Block-ID youngengineers_logic:und_gatter fest, registrieren Block und BlockItem und fügen das Item dem Kreativinventar hinzu.
  2. Blickrichtung speichern: Der Block erhält eine horizontale FACING-Eigenschaft. Beim Platzieren richtet er sich nach der Spielerposition aus.
  3. Ausgangszustand speichern: Eine boolesche Eigenschaft POWERED zeigt an, ob Q gerade 0 oder 15 ist.
  4. Eingänge lesen: Bei Änderungen an Nachbarblöcken lesen wir das eingehende Redstone-Signal an den zwei festgelegten Seiten A und B. Dabei muss verhindert werden, dass unser eigener Ausgang als Eingang gezählt wird.
  5. Logik berechnen: Wir rufen UndLogik.signalstaerke(a,b) auf und aktualisieren bei Bedarf POWERED.
  6. Ausgang anbieten: Wir liefern das Redstone-Signal ausschließlich an der Q-Seite, benachrichtigen die Nachbarn über Zustandsänderungen und prüfen, ob Repeater sowie andere Logikblöcke das Signal erkennen.

Technischer Prüfpunkt: Die vollständigen Methoden und Signaturen zur Redstone-Abfrage, Blockrotation, Nachbaraktualisierung und Signalabgabe sind von den Mappings und der API der tatsächlich verwendeten Minecraft-/Fabric-Version abhängig. Deshalb ist dieser Abschnitt noch keine kopierfertige Fabric-Blockklasse. Wir ergänzen sie erst nach dem ersten erfolgreichen Gradle-Build der Mod für Minecraft 26.2. Ungeprüfte API-Aufrufe wären für Schüler besonders frustrierend.

7. So prüfen wir später den echten Block in Minecraft

Baue eine kleine Testanlage auf einer ebenen Plattform:

  1. Starte Minecraft in einer separaten Entwicklungs- oder Testinstanz.
  2. Gib dir den neuen Block mit /give @s youngengineers_logic:und_gatter, sobald er registriert ist.
  3. Platziere ihn so, dass Q nach Süden zeigt.
  4. Verbinde A und B mit je einer getrennten, schaltbaren Redstone-Leitung. Die Leitungen dürfen sich nicht berühren.
  5. Schließe an Q zuerst eine Lampe an und teste die vier Eingangskombinationen.
  6. Ersetze die Lampe testweise durch einen Repeater. Prüfe, ob dieser zuverlässig angesteuert wird.
  7. Drehe den Block nach Osten, Norden und Westen und wiederhole die vier Tests.

Abnahmekriterien: 4 Eingangskombinationen × 4 Blockausrichtungen = 16 Tests. Hinzu kommen ein Test mit Signalstärke 1, ein Test mit Signalstärke 15 und ein Test der Signalweitergabe an einen Repeater.

8. Fehlersuche und Verbesserungen

Der Java-Test schlägt fehl

Prüfe die Bedingung eingangA && eingangB und die Umwandlung signal > 0. Die Testwerte müssen 0 oder 15 ergeben.

Der Block erscheint nicht im Kreativinventar

Blockregistrierung, BlockItem, Initialisierung und die Registrierung in einer Kreativregisterkarte prüfen.

Q leuchtet auf der falschen Seite

Die Blickrichtung des Blocks und die Ableitung der Seiten A, B und Q prüfen. Nach einer Drehung dürfen die Anschlüsse nicht an ihren Welt-Himmelsrichtungen kleben bleiben.

Die Lampe funktioniert, der Repeater nicht

Die gerichtete Redstone-Ausgabe und Nachbaraktualisierung prüfen. Ein optisch leuchtender Block beweist noch nicht, dass er ein echtes Redstone-Signal liefert.

Das Spiel friert ein oder Signale flackern

Prüfe, ob Zustandsänderungen nur bei tatsächlich geändertem Q ausgelöst werden und ob Nachbaraktualisierungen eine unendliche Rückkopplung erzeugen.

9. Drei Erweiterungen für unsere AG

ODER-Block: Ändere die Java-Funktion zu a || b. XOR-Block: Verwende a ^ b. NOT-Block: Ein Eingang und !a. Anschließend erhält jeder Block ein eigenes Symbol auf der Textur.

Forscherauftrag: Entwickle ein Zwei-Schalter-Schloss, das nur dann öffnet, wenn A = 1 und B = 0 ist. Welche Gatter werden benötigt?

Status dieses Kurses: Die Wahrheitstabelle, der interaktive Browser-Simulator und die reine Java-Logik sind vollständig dokumentiert. Die konkrete Fabric-Implementierung und der Minecraft-26.2-Praxistest stehen noch aus. Der Kurs unterscheidet bewusst zwischen geprüftem Grundprinzip und versionsabhängiger Implementierung.
